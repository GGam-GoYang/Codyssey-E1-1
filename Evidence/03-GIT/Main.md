# Git 주요 개념

[← README로 돌아가기](../../README.md)

## 1. Git과 GitHub

| 구분 | 역할 |
| --- | --- |
| Git | 파일의 변경 이력을 커밋으로 기록하고 관리하는 버전 관리 도구 |
| GitHub | Git 원격 저장소를 호스팅하고 코드 공유 및 협업 기능을 제공하는 서비스 |

- Git의 커밋은 로컬 저장소에 기록됨.
- 로컬 커밋을 GitHub에 올리려면 푸시가 필요함.
- Git 작성자 정보 설정과 GitHub 로그인은 별개임.

## 2. Git 사용자 정보 및 기본 브랜치 설정

| 명령어 | 의미 |
| --- | --- |
| `git --version` | 설치된 Git 버전 확인 |
| `git config --global user.name "이름"` | 커밋 작성자 이름 설정 |
| `git config --global user.email "이메일"` | 커밋 작성자 이메일 설정 |
| `git config --global init.defaultBranch main` | 새 로컬 저장소 생성 시 기본 브랜치 이름을 main으로 설정 |
| `git config --list` | 현재 적용되는 Git 설정 목록 확인 |

- `--global`은 현재 OS 사용자의 Git 설정에 적용됨. 저장소별 설정이 있으면 해당 값이 우선 적용될 수 있음.
- Ubuntu VM과 Windows는 서로 다른 환경이므로 Git 설정도 각각 적용됨.
- 작성자 이름은 GitHub 아이디와 같을 필요가 없음.
- GitHub에서 제공하는 `noreply` 이메일을 사용하면 개인 이메일 대신 해당 주소를 커밋 작성자 정보로 사용함.
- 이메일 설정을 바꿔도 기존 커밋의 작성자 이메일은 변경되지 않음.
- `init.defaultBranch` 설정은 기존 저장소의 브랜치 이름을 변경하지 않음.

## 3. 로컬 저장소와 원격 저장소

| 용어 | 의미 |
| --- | --- |
| 로컬 저장소 | 내 컴퓨터에서 파일과 변경 이력을 관리하는 저장소 |
| 원격 저장소 | GitHub 등 원격 위치에 있는 저장소 |
| Clone | 원격 저장소의 파일과 변경 이력을 로컬로 복제하는 작업 |
| origin | 복제 시 기본으로 등록되는 원격 저장소 이름 |
| main | 이번 저장소에서 사용하는 브랜치 이름 |
| origin/main | 로컬 Git이 마지막으로 확인한 origin의 main 브랜치 상태 |

- 공개 저장소는 로그인하지 않아도 복제할 수 있음.
- 복제 성공과 GitHub 로그인 성공은 구분해야 함.

## 4. 변경 사항 기록 및 업로드

수정 → 저장 → 스테이징 → 커밋 → 푸시 순서로 진행함.

| 단계 | 의미 | VSCode에서 수행한 작업 |
| --- | --- | --- |
| 수정 및 저장 | 작업 파일의 내용을 변경하고 저장 | Git.md 편집 후 저장 |
| 스테이징 | 다음 커밋에 포함할 변경 선택 | 소스 제어에서 파일 옆 `+` 선택 |
| 커밋 | 스테이징한 변경을 로컬 저장소의 이력으로 기록 | 커밋 메시지 작성 후 커밋 |
| 푸시 | 로컬 커밋을 원격 저장소에 전송 | 소스 제어에서 푸시 실행 |

- 파일 저장만으로 커밋이나 GitHub 업로드가 진행되지는 않음.
- 커밋 메시지는 변경 내용을 알아볼 수 있도록 작성함.
- 커밋 메시지 편집 화면에서 `#`으로 시작하는 안내 줄은 메시지에서 제외됨.

## 5. Pull과 Push

| 명령어 | 의미 |
| --- | --- |
| `git pull` | 원격 변경을 가져와 현재 브랜치에 통합 |
| `git push` | 로컬 커밋을 원격 저장소에 전송 |

- 원격 브랜치에 로컬에 없는 커밋이 있으면 푸시가 거절될 수 있음.
- 이번 실습에서는 먼저 풀로 원격 변경을 통합한 뒤 푸시함.
- 로컬과 원격 양쪽에 커밋이 있어 병합 커밋이 생성됨.
- Pull의 통합 방식은 설정이나 옵션에 따라 병합 또는 rebase가 될 수 있으며, 항상 병합 커밋이 생성되는 것은 아님.
- 충돌이 발생하면 충돌 내용을 해결한 뒤 진행해야 함. 이번에 병합 커밋이 존재한다는 사실만으로 충돌 발생을 의미하지는 않음.

## 6. 실습 환경 및 검증

- Ubuntu VM에서 Git 버전과 사용자 정보, 기본 브랜치 설정을 확인함.
- Windows VSCode에서 저장소 복제, GitHub 로그인, 문서 편집 및 커밋·푸시를 진행함.
- VSCode 계정 메뉴에서 GitHub 로그인 상태를 확인함.
- GitHub에 파일 내용과 커밋이 반영된 것을 확인하여 원격 저장소 업로드를 검증함.
